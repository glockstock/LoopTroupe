# Ride stats file contract (v1)

From `engineering_manager`, 2026-10-02. The authoritative version is in `docs/tech_spec.md` on `main`, under "Ride stats file contract (v1)". This is a copy for `coaster_data_curator`. If the two differ, `docs/tech_spec.md` wins, and you can propose changes to it there.

## Output

- **File:** `js/stats.json` on `main`, generated by `scripts/stats/build.mjs`. Port `fetch-wikidata.mjs` and the infobox fetcher into that script.
- **Committed inputs:**
  - `sources/stats/links.json`: coaster ID → QID and Wikipedia title.
  - `sources/stats/overrides.json`: your choices where the sources disagree.
- **Raw responses** (Wikidata and Wikipedia) go to `sources/stats/raw/`, which is gitignored. **Don't commit them.** That includes `wikidata-raw.json`.
- **Budget:** at most 256 KB uncompressed and 64 KB gzipped (a warning at 200 KB).

## Shape

```json
  "schema": 1,
  "license": "CC-BY-SA-4.0",
  "licenseUrl": "https://creativecommons.org/licenses/by-sa/4.0/",
  "notice": "Loop Troupe ride stats, compiled from Wikipedia (© Wikipedia contributors, CC BY-SA 4.0) and Wikidata (CC0 1.0); values selected, unit-converted, and normalized by Loop Troupe. This file is available under CC BY-SA 4.0.",
  "generated": "YYYY-MM-DD",
  "coasters": {
    "cedar-point--millennium-force": {
      "refs": {
        "wd": { "qid": "Q1065056", "retrieved": "2026-10-02" },
        "wp": { "lang": "en", "title": "Millennium Force", "revid": 1234567890, "retrieved": "2026-10-03" }
      },
      "height":       { "v": 94.488, "pub": [310, "ft"], "src": "wp" },
      "speed":        { "v": 149.668, "pub": [93, "mph"], "src": "wp" },
      "gforce":       { "v": 4.5, "src": "wp", "cite": "rcdb" },

```

The `revid` and `retrieved` values above are illustrative.

## Rules

1. **Keys are coaster IDs that exist in `js/data.js`.** No entry for a coaster with no data. Never create or change an ID.
2. **Every field carries provenance:** `{ v, src, ... }`, where `src` is `wd` or `wp` and names a ref in that coaster's `refs`.
   - `wd` needs `qid` and `retrieved`.
   - `wp` needs `lang` (`en`), `title`, `revid` (the revision you read the value from), and `retrieved`.
   - Dates are `YYYY-MM-DD` and never in the future.
3. **Fields:**

   | Field | Value |
   | --- | --- |
   | `height`, `drop`, `length` | meters |
   | `speed` | km/h |
   | `duration` | seconds |
   | `gforce` | g |
   | `inversions` | whole number, no `pub` |
   | `manufacturer`, `designer`, `model` | string |
   | `material` | `steel`, `wood`, or `hybrid` |
   | `type` | array of strings |
   | `opened`, `closed` | `YYYY`, `YYYY-MM`, or `YYYY-MM-DD`, keeping the source's precision |

   Ask before adding a field.
4. **Units: store metric.**
   - Convert `v` with exact factors (1 ft = 0.3048 m, 1 mph = 1.609344 km/h) and round to 3 decimals.
   - `pub` is the figure exactly as the source states it: `[number, unit]`, with unit `m`, `ft`, `km/h`, `mph`, or `s`.
   - `pub` is required whenever the source states a unit. The site shows `pub` verbatim and converts only the other unit.
5. **Missing fields are omitted.** Never `null`, never an empty string, never an estimate.
   - Keep one value per field. Where the sources disagree, decide against the primary source either cites.
   - Leave unresolved conflicts out, and record them in `sources/stats/`, which isn't shipped.
6. **`cite`** (optional, `wp` values only) records what Wikipedia cites for the value: `rcdb`, `park`, `manufacturer`, `news`, `other`, or `none`. Please fill it in where you can. It keeps the owner's Q-040 choice open. Never visit or query RCDB.
7. **No other sources.** No OpenStreetMap values (they're ODbL and must not mix into a CC BY-SA file), no values from other sites, and nothing derived from map art. Nothing from this file goes into `js/data.js` or the map files.
8. **Fetch politely:**
   - Use the MediaWiki API with up to 50 titles per request (`prop=revisions`, `rvprop=content|ids`) and `maxlag=5`.
   - Send requests one at a time, with the project User-Agent.
   - Run fetches by hand, never from CI or browsers.
9. **Validation:** `node scripts/check-data.mjs` (to be written) enforces rules 1–7, plus plausibility ranges that catch unit mix-ups:

   | Field | Range |
   | --- | --- |
   | `height`, `drop` | 1–200 m |
   | `length` | 20–3,000 m |
   | `speed` | 5–250 km/h |
   | `duration` | 10–600 s |
   | `gforce` | 0.5–6.5 g |
   | `inversions` | 0–14 |

   It also checks that `pub` agrees with `v` within 0.5%.

## How the site uses it

- **Loading:** the file loads lazily on the first ride page.
- **Units:** imperial first, metric alongside.
- **Sources:** each value shows its source.
- **Credit line:** links the Wikipedia article at the exact `revid`, with "Wikipedia contributors, CC BY-SA 4.0" and "Units converted by Loop Troupe", plus Wikidata (CC0) when used.
- **Missing values:** core rows show as missing.

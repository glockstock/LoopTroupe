# Spike: coaster stats from Wikidata

Question: how much ride-stat data ("speed, G force, etc") can Loop Troupe get from open sources for the 1,024 coasters in `js/data.js`, keyed by our coaster IDs?

Short answer: names, manufacturer, and type for about 45% of our coasters, but height, speed, and length for only about 4%, inversions for none, and G-force for none. See `coverage.md` for the numbers.

This is a spike. Nothing here is loaded by the app, and `js/data.js` is unchanged.

## Files

| File | What it is |
| --- | --- |
| `fetch-wikidata.mjs` | Fetches and builds everything. Node 18+, built-ins only. All five SPARQL queries are in the file. |
| `wikidata-raw.json` | The raw query results with the retrieval time. Lets the build rerun offline without calling Wikidata again. |
| `stats.json` | Stats keyed by coaster ID: QID, height, speed, length, duration, manufacturer, designer, type, opening and closing dates, and the retrieval date. |
| `links.json` | `{ coasterId → QID }` with a confidence level (`high` or `medium`) and the evidence for each match. |
| `ambiguous.json` | Matches the script would not make on its own. A person needs to decide these. |
| `coverage.md` | Coverage report. Generated by the script, so don't edit it by hand. |

## Refresh

```sh
NODE_USE_ENV_PROXY=1 node spikes/coaster-stats/fetch-wikidata.mjs   # fetch, then build
node spikes/coaster-stats/fetch-wikidata.mjs --offline              # rebuild from wikidata-raw.json
```

You only need `NODE_USE_ENV_PROXY=1` behind an HTTPS proxy, because Node's `fetch` ignores `HTTPS_PROXY` otherwise. A full run sends 5 queries spaced 65 s apart and takes about 5 minutes. During an outage, WDQS throttled this client to 1 request per minute, and the script retries on 429 or a dropped stream. It sends the User-Agent `LoopTroupe-data/0.1 (https://github.com/glockstock/LoopTroupe)`.

The queries:

1. The item set: `?item wdt:P31/wdt:P279* wd:Q204832 ; wdt:P17 wd:Q30`, plus coasters with no country whose park is in the US. The subclass path is fast (about 1 s).
2. Item and string claims (park P361/P276, P131, manufacturer P176, designer P287, type P31, RCDB ID P2751, and so on), with labels.
3. Quantities with units (height P2048, speed P2052, length P2043, duration P2047) and dates with precision (opening P1619/P580/P571; closing P3999/P582/P576), with statement rank.
4. Labels, aliases, and the English Wikipedia title.
5. Context: description, US state, and park aliases. The transitive `P131*` only stays fast with `hint:Query hint:optimizer "None"`. Left to the optimizer, it starts from the states and times out.

Labels are English, falling back to Wikidata's language-neutral `mul` label.

## Units

Each value keeps the unit Wikidata stored, and the script computes the other unit: height and length in `m` and `ft`, speed in `km/h` and `mph`, and duration in seconds. When Wikidata holds the same figure in two units, the imperial one is kept, because US parks publish imperial figures. A converted value can be slightly off the published one. For example, X2 is stored as 53 m, which converts to 174 ft, but the published figure is 175 ft. So display the stored unit as primary, or round conversions for display.

## Matching

A Wikidata item is linked to a coaster ID only when the name matches and the location confirms it.

- **Name:** the Wikidata label, English Wikipedia title, or alias, normalized for case, accents, punctuation, `&`, and a leading "The". Inside a confirmed park, a sponsor prefix or subtitle is also allowed ("Pepsi Orange Streak" matches "Orange Streak").
- **Location, strongest first:** the park name or alias, or a description naming the park; then the city; then the state alone. The state is accepted only when Wikidata gives no park and the name is unique among our coasters in that state.
- **Dropped:** candidates in another state, or at a different local park. Carowinds counts as both NC and SC.
- **Sent to `ambiguous.json`:**
  - several candidates;
  - several Wikidata items for one ID;
  - one item that matches several of our IDs (for example Top Thrill Dragster and Top Thrill 2, Twisted Twins and Storm Chaser, or a relocated ride listed at two parks);
  - matches through a Wikipedia title only (the Wikidata label disagrees);
  - name matches with no location data.
- No IDs are created or changed.

## Limits

- **Coverage is thin where it matters.** Wikidata has 635 US roller coasters, against our 1,024. Of the 462 we match, only 39 have any of height, speed, or length, and only 13 have all three. Manufacturer (85% of matched) and type (96%) are the useful fields.
- **Inversions:** Wikidata has no property for number of inversions, so this field is `null` everywhere.
- **G-force:** no open structured source has it. Wikidata has no property for it, and the OpenStreetMap roller-coaster tagging (`attraction=roller_coaster`) documents no G-force, inversion, height, or speed keys. The only open place it appears is the `gforce` field of English Wikipedia's roller-coaster infobox. A Wikipedia search on 2026-10-02 found 311 of about 888 infobox articles worldwide with a numeric value; US coverage is a subset. Wikipedia is **CC BY-SA 4.0**, so its content comes with attribution and share-alike obligations. Using it would be a separate decision for the owner, and is not done here. Park and manufacturer G-force figures are not openly licensed.
- **Freshness:** Wikidata lags real-world changes. X2 closed in July 2026 per Wikipedia, but Wikidata has no closing date for it. Wild Mouse (Cedar Point, 2023) has no item at all. Many new 2025–2026 coasters exist on Wikidata without figures.
- **Data quality:** Wikidata has duplicate items (shared RCDB IDs), items with no English label, wrong labels (the item for Emperor at SeaWorld San Diego is labelled "Mako"), and conflicting values. `coverage.md` lists the ones the script found.
- Model names are thin. `type` is the P31 class (for example "inverted roller coaster" or "Boomerang"), and `model` (P144 "based on") is rarely set.
